# Full source trace and proposed evidence boundaries

This is descriptive, not executable. References resolve to preserved files in source-inventory.json.

## Old runner and new required boundaries
- Old runner hashes every packet input, loads its gate and claims a local attempt marker before native imports, verifies psycopg 3.3.8, inserts live Workers/Events source roots, then loads the fixture. It uses autocommit tuple rows, prepare_threshold=None; runner cursor execution disables preparation. New route must preserve native adaptation semantics and explicitly pin interpreter/driver/transitive binary libraries and available artifact paths.
- Setup connection checks old baseline, begins READ COMMITTED, creates roles/grant, installs full SQL and commits; close errors are preserved. Any setup commit exception prevents scenarios/disposal. A commit acknowledgement followed by close failure still halts.
- Fixture scenarios run sequentially, each owning fresh bounded connections and pending tasks. After all return, old runner rechecks pins and all handle closure. Disposal has its own pre/post state checks and transaction. New runner must improve physical/full dependency checks rather than merely point old code at new target.

## SQL admission trace
W01 rejects non-READ-COMMITTED with PZ005 and invalid arguments/canonical/protected material with PZ006 before relation or sequence operations. Wide schema versions produce blocked_schema/intake_blocked; representable int4 produces queued/intake_runnable, not handler capability.
It captures direct/key candidates with E15 and raw shared rows in one statement snapshot, validates every candidate's integrity before deciding conflict, and returns a lawful existing work ID with inserted=false only after the immutable comparator. Corrupt family/half/projection is PZ012; split or immutable mismatch is PZ002.
An empty family permits exactly one targetless INSERT ON CONFLICT DO NOTHING reservation. An actual uniqueness loser receives one new complete capture, no second insertion or retry loop. A winner updates its own work timestamp, inserts job_payloads and one work_history row, then returns staged inserted=true. It does not commit or prove same-command E15; the fixture follows with a separate command. The history sequence may advance despite rollback, so gapless/physical rollback claims are invalid.

## All twelve scenario invocations (35 connections)
1. serial: 3 connections. One READ COMMITTED root tests new pair/intake; same-ID, alternate-ID and raw-replay-spelling duplicates; 13 rebuilt same-ID immutable conflicts plus 3 keyed contenders (PZ002); no idempotency key; schema versions 2147483647, 2147483648 and 10**40; present material; distinct no-key insert; nine malformed raw arguments (PZ006). Full exact row delta and unrelated sequences checked, then root rollback with row audit. Two separate REPEATABLE READ/SERIALIZABLE roots expect PZ005 and rollback.
2. corruption: 1 connection. Lawful winner plus deliberately incomplete raw Work, never committed, establishes PZ012 precedence over request conflicts for direct/key family shapes. Root rollback and complete row audit.
3-6. Four commit races: 3 connections each. same_id false/true crossed with conflict false/true. Actual blocking-pid observation orders the race. Winner commit acknowledged; duplicate loser returns winner/false or conflicting loser raises PZ002. Loser rollback, no loser sequence allocation, exact committed winner row delta. Four committed winners remain.
7-8. Two abort races: 3 connections each. same_id false/true. First owner rolls back; blocked contender becomes inserted=true, gets pair/intake check, then rolls back. Exact root rows restored; history sequence gaps allowed.
9. lock timeout: 3 connections, lock_timeout 1000ms. Expect 55P03 without receipt; loser then winner rollback; unchanged loser footprint and row rollback audit.
10. statement timeout: 3 connections, statement_timeout 1000ms. Expect 57014 without receipt; corresponding rollback/footprint checks.
11. split race: 4 connections. Two lawful uncommitted owners, contender and read-only observer. Observed blocker determines commit order: nonblocking owner first, blocking owner last. Both commits acknowledged; contender must raise PZ002, rollback and allocate no sequence. Exact two-winner delta; two committed winners remain.
12. deadlock: 3 connections. Two actual prior W01 reservations and two pending opposite contenders form a native cycle. Require 40P01, no victim receipt; rollback victim, surviving insert returns inserted=true then rolls back. Complete row rollback check.

The source invocation order is serial, corruption, two commit races then abort for same_id=false, two commit races then abort for same_id=true, two timeout cases, split and deadlock. The grouped numbering above categorizes scenarios without changing that order.

The complete footprint enumerates 12 tables: attempts, delivery_history, finalization_guards, inbox, job_payloads, mutation_operations, outbox, publication_history, schema_versions, subscriptions, work, work_history. It compares Counter multisets of full rows/bytes and scalars last_value/log_cnt/is_called of delivery_history_history_id_seq, publication_history_history_id_seq, work_history_history_id_seq. The inventory rejects unexpected ordinary/partitioned tables or sequences. Pair checks use actual E15, raw work/half/history fields, intake state/time, identity and metadata. No-write checks include every sequence scalar; root rollback permits only work_history sequence variation. No setval or fabricated gapless evidence.

## Budgets to preserve or explicitly revise under review
Old arithmetic: serial 3 + corruption 1 + eight ordinary races 24 + split 4 + deadlock 3 = 35 fixture attempts; setup 1 + disposal 1 = 37 total, maximum 4 live simultaneously. Failed attempts count; no retries. Extra verification connections must not appear for free.
External 180-second wall timeout is declared in packet but not enforced inside old runner. The new controller must prove enforcement and child/thread termination handling. Native connect timeout 5s; session statement 8s, lock 6s, idle-in-transaction 12s; observer barriers up to 4s; Pending.finish default 10s; deadlock observation up to 8s. Timeout scenarios lower one timeout to 1s.
Pool cleanup uses cancel_safe(timeout=2), then waits up to 10s per active task; after closes it can wait 2s per remaining task. Cumulative cleanup can exceed a simplistic per-scenario estimate. Global deadline/output/memory/process bounds and controller receipts need exact new design review within the captured 384MiB/0.5CPU/128PID target profile. Do not silently claim the old declaration proves safety under all failure paths. No new resource ceiling is invented as an accepted value.

## Error, uncertainty and aftermath
Expected-error paths snapshot, create savepoint, invoke, roll back to savepoint and release only after successful rollback-to. Wrong exception/sqlstate, absent error or cleanup failure is fatal; BaseException is preserved. Savepoint recovery does not prove business-root rollback.
Pool.commit records uncertain exceptions and raises; no resubmission. Thread ownership registers before launch; a start exception is possibly-started unless construction failed before launch. No retry of launch. Cleanup cancels before rollback so main and worker do not use a live connection concurrently. If call completion is unconfirmed, force-close is cancellation/disconnection, not proof of server cleanup; report grouped failures with original diagnostics. Any active thread, failed rollback/cancel/close or external timeout prohibits disposal and requires separate read-only reconciliation scope.
A returned admission pair is staged evidence, not durable business completion. Setup/scenario/disposal commits require distinguishable acknowledgements and aftermath. Ambiguous network/controller loss preserves last confirmed phase and pins; no automatic repair, retry, role deletion or dropping leftover schemas. Capture errors without credentials or payload dumps and retain exact bounded receipts.
